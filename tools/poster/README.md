# 分享长图 / PDF

微信里转发用的一张图，把包赔规则讲完，右下角二维码扫了直接弹出官网的
「三步开始跟单」。产物提交在 `assets/share/`，官网合作伙伴板块挂着下载
按钮。

## 重新生成

```sh
bash tools/poster/build.sh
```

## 为什么产物要入库

站点是 GitHub Pages 纯静态托管，没有构建环节——文件不在仓库里就没有下载
地址。所以 PNG 和 PDF 跟着代码一起提交。

## 改条款时必须一起重出

海报会被下载、转进微信、脱离官网独立流传。改了官网忘了海报，外面就长期
挂着一份旧条款，而且**撤不回来**——已经转出去的图改不了。

`build.sh` 第一步会跑 `terms.py`，把海报上的关键数字逐个回官网页面里核对
（保护期、赔付上限、到账时限、跟单参数、IB 门槛、分成比例……）。对不上就
直接退出、不出图。**宁可出不来，也不要出一张和官网不一致的。**

改了条款之后：先改官网页面 → 改 `poster.html` → 跑 `build.sh`。如果只改了
官网没改海报，`terms.py` 会把不一致的项列出来。

## 二维码

指向 `https://presighttrading.com/#start-copy`。这个 hash 由 `app.js` 处理，
落地后直接弹出「三步开始跟单」弹窗——扫码的人手里没有页面上下文，落在首页
顶部还得自己找入口，一步都不该多。

不要改成 `#start`：那是「四步开始跟单」那一节已经占用的锚点，重名会让浏览器
先滚过去再弹窗，观感很乱。

纠错等级用 H：长图会被反复转发、压缩、截屏，容错留足一点。

## 校验是真的会拦住的

写完之后验过一遍：把 protection.html 里的「1 个月（30 个自然日）」改成
「2 个月（60 个自然日）」，`terms.py` 退出码 1 并指名道姓报出

```
保护期（海报写「1 个月（30 个自然日）」）在 protection.html 里找不到对应内容
```

**第一次验的时候它没拦住**——因为我拿来做测试的替换串写的是
`1 个月 &mdash; 30 个自然日`，而页面上其实是全角括号 `1 个月（30 个自然日`，
替换根本没生效，校验器压根没被挑战到。这类"测试本身没跑到"的假绿灯，比
没有测试更危险，所以这里把结论记下来：改了校验规则之后，一定要真的改坏
一次源文件，确认它报错。

## 五个语种各一份

`poster.tpl.html` 是模板（只有版式，正文全是 `{{占位符}}`），
`strings.py` 放五套文案，`render.py` 合成后交给 `build.sh` 截图。

产物：`assets/share/presight-baopei-{zh,en,ja,vi,th}.{png,pdf}`。
无后缀的 `presight-baopei.png/pdf` 保留为中文版的副本——之前发出去的下载
链接是无后缀的，已经转进微信的链接不该失效。

二维码也按语种分开：`qr-{lang}.svg` 各自指向 `/{lang}/#start-copy`，
扫码的人落在自己语言的页面上，而不是被甩去中文版。

`render.py` 渲染完会自检两件事，任一不过就直接失败、不出图：
1. 还有没有没替换掉的 `{{占位符}}`——漏一个就会在图上留下一串花括号；
2. 非中日语种的正文里还有没有汉字——漏翻一段最容易以这种形式出现。

改文案只改 `strings.py`，不要直接改 `poster.tpl.html` 的正文。
